<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator → DB_PATH env var | Operator-controlled env var sets the SQLite file path; no end-user input in Phase 1 |
| Backend process → SQLite file | init_db() opens and modifies the SQLite file; schema is a hardcoded constant |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | DB_PATH env var path traversal | accept | Env vars are operator-controlled in a single-container deployment; no end-user input reaches DB_PATH; acceptable risk |
| T-01-02 | Tampering | SQL injection via SCHEMA_SQL | accept | SCHEMA_SQL is a hardcoded string constant — no user input is interpolated; no injection vector exists |
| T-01-03 | Tampering | Concurrent writes / SQLite locking | accept | Single-user app; one-connection-per-request pattern + SQLite's built-in serialized writes; WAL mode not required |
| T-01-04 | Denial of Service | init_db() crash on restart | mitigate | CREATE TABLE IF NOT EXISTS + INSERT OR IGNORE make init_db() idempotent — tested in test_idempotent_on_second_call |
| T-01-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed in this phase; sqlite3, os, uuid, logging are all Python stdlib |
</threat_model>
